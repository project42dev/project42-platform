# Design a Bounded Agent Loop: reduced-motion presentation

Present every visual as a complete static composition. Do not make completion
depend on animation timing, autoplay, or pointer gestures.

## workflow-or-agent

Present both columns and every comparison row simultaneously.

Text alternative: The fixed workflow uses code-defined checks and one write. The model-directed loop may propose a next action for necessary variation, but the controller still owns authority, budgets, execution, evidence, terminals, and recovery.

## work-order-contract

Show the complete card with numbered fields and no animation.

Text alternative: The card defines one receipt, in-memory scope, trusted controller inputs, no external effects, independent verification, and five terminals.

## trust-boundary

Show both lanes and all labels in one static diagram.

Text alternative: Policy, limits, state, verifier, and approvals are trusted controller inputs. Observations and decisions can propose but cannot grant authority.

## state-and-transition

Display the complete transition and both state snapshots without movement.

Text alternative: The sequence is inspect, decide, authorize, preflight, act, verify, and record. A successful write moves revision one to revision two and requires verifier acceptance.

## terminal-outcomes

Show all five cards in a static table.

Text alternative: COMPLETE requires verified evidence. NEEDS_HUMAN follows three no-progress transitions. BUDGET_EXHAUSTED blocks preflight overspend. POLICY_BLOCKED rejects malformed or unauthorized work before effects. FAILED_WITH_RECOVERY_EVIDENCE preserves an unknown consequential outcome.

## unknown-outcome-recovery

Present the original result and reconciliation result together without animation.

Text alternative: The uncertain write may have created a receipt. Recovery finds one effect by operation key and performs no retry while preserving FAILED_WITH_RECOVERY_EVIDENCE.
