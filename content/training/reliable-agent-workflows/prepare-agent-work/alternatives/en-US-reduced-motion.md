# Design a Bounded Agent Loop: reduced-motion presentation

Present every visual as a complete static composition. Do not make completion
depend on animation timing, autoplay, or pointer gestures.

## workflow-or-agent

Show both designs and every comparison row simultaneously.

Text alternative: Fixed workflows use code-defined paths. Bounded agents may select the next action, but require explicit authority, budgets, evidence, terminal outcomes, and recovery.

## work-order-contract

Present the completed card as a static form with numbered fields.

Text alternative: The card lists outcome, allowed scope, trusted inputs, constraints, non-goals, required evidence, approval owner, and stopping conditions.

## work-order-demonstration

Show the before and after text in two static columns.

Text alternative: The bounded request limits one guide, names approved evidence, protects policy and permissions, requires review, link, and render evidence, and escalates source conflict.

## trust-boundary

Show both lanes and the reject-or-escalate rule in one static diagram.

Text alternative: Trusted work order and policy define authority. Retrieved pages, issues, logs, tools, memory, and agent messages remain untrusted observations.

## state-and-transition

Display the full transition sequence and state fields without animation.

Text alternative: The state ledger records contract, facts, evidence, actions, approvals, budgets, and allowed decisions. Finish requires independent success evidence.

## terminal-outcomes

Show all terminal definitions in a static table.

Text alternative: Succeeded, failed, unknown, needs approval, refused, cancelled, budget exceeded, and repeated non-progress each require different evidence and next steps.

## recovery-checkpoint

Present checkpoint fields and recovery routes in a numbered static table.

Text alternative: The checkpoint records contract, state, facts, actions, approvals, results, postconditions, uncertainty, budgets, and allowed decisions before resume or handoff.
