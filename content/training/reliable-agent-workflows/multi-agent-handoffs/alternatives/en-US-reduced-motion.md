# Build Auditable Multi-Agent Handoffs: reduced-motion presentation

Present every visual as a complete static composition. Do not make completion
depend on animation timing, autoplay, or pointer gestures.

## delegate-or-transfer

Show both flows in a static side-by-side comparison.

Text alternative: Delegation keeps the parent active and returns a typed artifact. Handoff makes the specialist active until a declared return or escalation condition.

## handoff-packet-demonstration

Present the complete packet and validation checklist in one static view.

Text alternative: The packet contains schema, trace, sender, recipient, reason, goal, constraints, facts, artifacts, actions, permissions, budget, success, and return states.

## handoff-validation-demonstration

Show both packet checklists and outcomes simultaneously.

Text alternative: Packet A has the correct recipient, sourced claims, narrow actions, denied publication, and return states. Packet B fails recipient, provenance, authority, and terminal checks.

## filter-and-reauthorize

Show allowed and removed context beside allowed and denied permissions.

Text alternative: Only required facts and artifacts pass the context filter. The recipient receives only actions allowed by its policy and not denied by the packet.

## accept-return-and-escalate

Display the entire handoff state machine without animated transitions.

Text alternative: Validated packets may be accepted or rejected. Accepted work returns a typed result. Zero work turns pauses, while rejection and ambiguous timeout follow separate paths.

## provider-mappings-and-tests

Show invariant rows and provider adapter columns as a static matrix.

Text alternative: Recipient, context, authority, trace, recursion, failure, side-effect, and return invariants remain constant while provider mechanisms differ.

## handoff-invariants-lab-narration

Show the two gates as a static diagram.

Text alternative: The validation gate checks structure, provenance, consistency, recipient, event, depth, and budget. The authorization gate calculates effective actions.

## worked-handoff-example-lab-narration

Present Packet, Policy, and Result as static columns.

Text alternative: The packet requests read and publish, policy allows read and comment, denied actions include publish and delete, and the result has read and two remaining turns.

## eight-scenario-traces-lab-narration

Show the eight traces in a static three-column grouping.

Text alternative: Correct transfer and narrowed excessive permission are accepted. Wrong recipient, missing provenance, poisoned context, and recursive bounce are rejected. Timeout and receiver rejection escalate.

## node22-repair-lab-lab-narration

Show the defect, filter equation, and before-and-after outputs without animation.

Text alternative: The starter has twenty learner passes out of twenty-two because sender actions are copied. The repair produces twenty-two out of twenty-two and pass.

## recovery-and-variation-lab-narration

Show both recovery paths in a static comparison.

Text alternative: Local recovery reruns tests after restoring the learner file. Runtime recovery preserves the ledger and escalates after ambiguous timeout.

## ecosystem-transfer-lab-narration

Show the four layers as a static stack.

Text alternative: Model family, runtime or API, and agent adapter are separate from application validation, authorization, budgets, and idempotency.

## activity-rubric-lab-narration

Show the rubric as a static checklist.

Text alternative: Every rubric claim requires a concrete artifact or trace, and fixture results must not be presented as live provider evidence.
