# Operate, Recover, and Improve Agent Systems: reduced-motion presentation

Present every visual as a complete static composition. Do not make completion
depend on animation timing, autoplay, or pointer gestures.

## classify-before-changing

Present the complete failure-classification matrix statically.

Text alternative: Each boundary lists representative failures, evidence, containment choices, and the owner who can change it.

## triage-and-contain

Show the severity and containment decision table in one static view.

Text alternative: Affected users, data, authority, effects, cost, availability, and obligations determine severity before pausing tools, routes, credentials, concurrency, or retries.

## reconcile-and-recover

Present the complete recovery decision tree without animated transitions.

Text alternative: The system of record and operation key determine actual postcondition; only transient, idempotent, budgeted failures may be retried.

## unknown-outcome-demonstration

Show the timeline, ledger record, destination evidence, and recovery outcome statically.

Text alternative: The responder pauses sending, checks one operation key, finds one destination message, verifies its postcondition, and performs no retry.

## runbook-and-communication

Display the entire runbook checklist as a static ordered table.

Text alternative: Each decision includes an owner, approval, exact target, evidence, expected result, failure path, and communication requirement.

## learn-and-improve

Show the complete improvement loop as a static flow.

Text alternative: Closure checks user outcome, external state, queues, authority, isolation, cost, and monitoring before prevention tasks receive owners and measures.
