# AI Systems and Useful Work: reduced-motion presentation

Present every visual as a complete static composition. Do not make completion
depend on animation timing, autoplay, or pointer gestures.

## complete-system-explanation

Display the full map at once. Use a persistent outline and numbered text label to identify the lane being discussed.

Text alternative: An AI model sits inside a larger system. Data and instructions enter the model; tools and permissions may enable actions; monitoring and people govern the outcome.

## system-boundary-demonstration

Show both complete columns and all comparison rows simultaneously. Emphasize the current row with text and a border.

Text alternative: The reviewed assistant uses approved notes and waits for a person. The automated system records sensitive data and performs external actions, creating additional privacy, authorization, and recovery requirements.

## capability-patterns-explanation

Present the entire matrix as a static table and identify the selected row with an explicit text prefix.

Text alternative: Each capability pattern is paired with a specific outcome, suitable evidence, and a way to test quality. No provider or model name substitutes for those requirements.

## assistance-automation-explanation

Show all authority levels as a numbered static list. Do not animate progression or imply that moving upward is always desirable.

Text alternative: Each step grants more action authority and therefore requires stronger evidence, permissions, monitoring, stop conditions, and recovery.

## human-accountability-explanation

Present the complete record as a static form. Use focus and a visible row label instead of animated reveals.

Text alternative: Accountability remains with people and organizations that choose the purpose, data, controls, action authority, and response when an AI-supported workflow causes error or harm.

## use-case-triage-demonstration

Show both completed rows at once. Mark the release decision in text and do not use color alone.

Text alternative: The low-consequence drafting task uses approved facts and review. The high-consequence denial task lacks sufficient evidence, appeal, and safe authority, so automation is rejected.
