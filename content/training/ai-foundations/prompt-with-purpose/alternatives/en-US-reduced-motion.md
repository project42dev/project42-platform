# Prompt with Purpose: reduced-motion presentation

Present every visual as a complete static composition. Do not make completion
depend on animation timing, autoplay, or pointer gestures.

## outcome-before-wording-explanation

Show all task-definition fields and the completed example simultaneously.

Text alternative: Customer feedback becomes group supplied comments, for the support lead, to choose three service fixes, for the next sprint, using permitted data.

## topic-to-task-demonstration

Present the original, each added field, and the final request in a static comparison.

Text alternative: The final request names the product owner, next iteration, supplied evidence, five-item limit, required fields, and missing-evidence behavior.

## context-and-trust-explanation

Display all labeled regions and the authority rule in one static diagram.

Text alternative: Instructions control the task. Trusted context supplies authorized facts. Untrusted documents and messages are analyzed as data and cannot change permissions or reveal protected instructions.

## constraints-and-contract-explanation

Show the full contract as a static four-column table.

Text alternative: Hard requirements include evidence and required fields. Preferences guide tone. The deliverable defines shape. Success checks decide pass or fail.

## observable-contract-demonstration

Display the vague and inspectable requests side by side with written review questions.

Text alternative: The contract requires issue, affected user, evidence quote, source identifier, confidence label, item limit, no identity inference, and conflict marking.

## stop-inspect-and-revise-explanation

Present all failure behaviors and diagnostic categories in a static flowchart.

Text alternative: Missing or conflicting information can cause ask, flag, narrow, unknown, or stop. Failures are classified as outcome, context, boundary, constraint, format, capability, tool, or verification.
