# Release and Reverse the Complete Serving Unit: reduced-motion presentation

Present every visual as a complete static composition. Do not make completion
depend on animation timing, autoplay, or pointer gestures.

## welcome-and-outcomes

Show the lifecycle as a static labeled list without animated transitions.

Text alternative: The lesson covers complete serving-unit inventory, candidate gates, bounded rollout, tested rollback, evidence, and a repair lab.

## change-unit-narration

Present the complete manifest as a static table and emphasize differences with text and borders.

Text alternative: Baseline and candidate columns list exact artifacts, contracts, policies, schemas, differences, owners, and retained locations.

## manifest-demonstration

Use a static table and static arithmetic lines.

Text alternative: The candidate adds a tokenizer, server image, safety template, and telemetry rename; memory rises from 8 to 9.2 gigabytes, a 15 percent increase.

## qualify-candidate-narration

Display the gates as a static table with text labels for pass, fail, hold, or missing evidence.

Text alternative: Quality, safety, security, compatibility, capacity, cost, and recovery each have explicit evidence, thresholds, owners, and dispositions.

## qualify-arithmetic-demonstration

Show the calculations as static text with no motion.

Text alternative: The observed safety value 0.05 exceeds the maximum 0.02 by 0.03, while cost 96 is below ceiling 100 by 4.

## stage-release-narration

Use a static strategy comparison and static packet fields.

Text alternative: A one percent simulated canary has a ten-minute observation window and a 120-second drain timeout; identity and readiness precede exposure.

## rollback-release-narration

Present rollback as numbered static states and a postcondition checklist.

Text alternative: The baseline uses conversation-v1 and the candidate uses conversation-v2; no reverse conversion exists, so recovery fails until the complete baseline readback is verified.

## rollback-postcondition-demonstration

Display the checklist without animated check marks.

Text alternative: A matching model digest alone is insufficient; all serving dependencies, schemas, and readiness must match the retained baseline.

## evidence-improvement-narration

Use a static ledger and numbered improvement list.

Text alternative: Approved and rejected candidates remain distinguishable, and findings update evaluation, compatibility, capacity, migration, and recovery evidence.

## repair-lab-narration

Present commands and expected outputs as static selectable text.

Text alternative: The learner repairs only src/decision.mjs; the incompatible fixture must reject on recovery, while the renamed compatible fixture must promote.

## repair-lab-commands

Display commands as static selectable text.

Text alternative: All commands are root-relative and bounded to the named lab; no live service or external integration is invoked.

## class-closing

Leave the closing card static.

Text alternative: Version, qualify, bound, rehearse, and verify the complete serving unit and its evidence.
