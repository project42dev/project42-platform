# Choose a Deployment Shape and Operating Model: reduced-motion presentation

Present every visual as a complete static composition. Do not make completion
depend on animation timing, autoplay, or pointer gestures.

## welcome-and-outcomes

Show the complete map at once. Use text headings and a persistent border for emphasis instead of animation.

Text alternative: The class starts with a workload contract and compares six deployment shapes using evidence about ownership, failures, recovery, and reversibility.

## workload-contract-narration

Display the complete form at once and identify the current group with a text heading and border.

Text alternative: The deployment decision begins with users, tasks, data, demand, latency, availability, failure behavior, retention, and recovery rather than a product choice.

## workload-demonstration

Present the entire workload card as a static, selectable table. Do not animate values or imply live measurement.

Text alternative: The worked workload serves 120 analysts, handles 60 requests per minute with bursts to 120, keeps confidential text in-country, and has explicit latency, availability, retention, and recovery objectives.

## shape-comparison-narration

Keep every row and column visible. Use a text marker and border to identify the current comparison cell.

Text alternative: Each deployment shape has different tradeoffs, and none automatically proves privacy, cost, performance, availability, or resilience.

## shape-matrix-demonstration

Show arithmetic and eligibility columns simultaneously. Do not sort or animate rows in a way that suggests score overrides eligibility.

Text alternative: The matrix gives scores of 18, 64, 78, 55, 92, and 73, but only on-premises service and hybrid satisfy all mandatory constraints.

## failure-domain-narration

Show all boundaries and dependencies simultaneously. Use numbered text descriptions for each proposed failure test.

Text alternative: Replicas protect against some process failures but shared host and control dependencies can remove every replica or block recovery.

## failure-domain-demonstration

Present the dependency, response, and evidence columns as a static table with text labels.

Text alternative: Each failure has a specific response, but the fixture does not perform live failure tests or prove recovery objectives.

## ownership-narration

Show the full matrix as a static table. Mark gaps with explicit text and a border.

Text alternative: The evaluation has qualified coverage for named responsibilities but lacks a qualified artifact-custodian substitute and after-hours incident command.

## reversible-choice-narration

Present the decision record as a numbered static sequence with every field visible.

Text alternative: The first shape is a staffed on-premises evaluation selected after constraints and ranking, with a tested safe return and explicit limits on the claim.

## repair-selector-lab-lab-narration

Show commands and outputs as selectable text in fixed panels. Do not animate execution or represent a live terminal.

Text alternative: The lab repairs eligibility-first selection, preserving validation and scoring, then verifies on-premises for baseline and cloud for changed evidence.

## class-closing

Show the complete closing rule as static text with no animation.

Text alternative: Define the work and failure behavior, assign ownership, apply constraints before ranking, choose a reversible shape, and stay within the evidence.
