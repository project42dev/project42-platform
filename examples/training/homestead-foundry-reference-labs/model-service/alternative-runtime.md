# Alternative model service mapping

Another runtime satisfies this lab when it can prove the same outcomes. The
implementation may use a workstation server, container, on-premises cluster, edge
runtime, or another managed compute service.

Map these fields explicitly:

- immutable model, tokenizer, conversion, image, runtime, driver, template,
  adapter, policy, configuration, and evaluation identities;
- request, response, streaming, error, cancellation, identity, readiness, and
  overload behavior;
- caller and operator principals, authorization, network, secret, audit, limits,
  revocation, and recovery;
- representative evaluation and load evidence for the exact serving build;
- secret-safe telemetry, cost attribution, alerts, and telemetry-loss detection;
- complete candidate qualification, bounded exposure, forced failure, rollback,
  and verified postconditions.

The alternative does not need Azure, Homestead Foundry, or an OpenAI-compatible
surface. If its interface differs, a local adapter translates the portable case
and evidence schemas without weakening the required outcomes.
